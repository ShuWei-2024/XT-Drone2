# 图像偏移、LIO 切片与 Odom 发布审计

日期：2026-10-20。隔离 PX4 1.17 / ROS 2 Jazzy / Gazebo Baylands。此报告解释特定诊断轮的 Odom 缺口，不替代长路线定位、重复性或实物验收。

## 结论与纠正

`−12 ms` 是此前加入临时估计器配置的图像时间敏感性试验值，**不是校准后的时钟偏差**。10 Hz LiDAR 与 30 Hz 相机的采样相位差，不能当作传输延迟或时钟偏差直接扣除。

当前适配器选择 LiDAR 时刻之后、30 ms 内的相机帧。示例：LiDAR `88.300 s`，原始图像 `88.308 s`；减去 12 ms 后，融合切片时刻变成 `88.296 s`，早于本帧 LiDAR。核心按切片时刻收集点，不会纳入这帧零逐点偏移的快照点云；如果没有可用的旧缓存点，这轮 LIO 不发布 Odom。

因此，不能把这两轮缺口概括为“原始 LiDAR 没点”“Python GC 暂停”或“视觉计算太慢”。切片时刻早于本帧不一定导致空切片：有时上一帧还在缓存中。必须结合实际点数判断。

**默认图像时间偏移仍为 0，没有放宽 250 ms 时效、20 ms 测量配对、0.20 m 冻结高度漂移或障碍净空保护。** 没有补造 Odom、修改测量时间、扩大接收等待窗口或空中拟合原点。

两轮所有有输出的 LIO 记录均满足：处理开始 ≤ 实际 publish 调用前 ≤ publish 调用后 ≤ 整轮处理结束。运行器确认原 PX4 基线保留、运行源码未变，正常清理退出。两轮被动健康检查均通过，说明单靠静态健康检查也不能把负偏移配置认证为可飞；此处采用实际切片记录判定。

核心重新构建通过；完整 Python 回归 **368 passed**（3 条既有 protobuf 弃用提示），核心 CTest **5/5 passed**。新增离线回归覆盖启动分离、旧云缓存、缺失/歧义关联、监督器与独立记录器的区别、固定偏移适用条件和已拒绝视觉提议不计作实际修正。

## 本次改动

- 核心审计 CSV 追加同步切片点数、去畸变点数、进入处理前的 IMU 初始化标志及未输出分类；原有列名保留。
- 增加实际 Odom `publish()` 调用前后单调时钟记录，避免再用整轮处理结束时刻替代发布时间。
- 新离线工具 `astra/tools/audit_livo_cut_timing.py` 按所选图像测量时间关联适配器、核心切片、核心 LiDAR 入缓存、独立记录器和监督器回调。它不把“最近的 LiDAR”冒充实际所选帧；关联歧义和缺失保留，在线时间偏移估计开启时拒绝套用固定偏移。
- 修复室外静态模式未初始化 `flight_precheck` 就读取的问题。首次静态尝试在仿真启动前退出，目录为 `cut_timing_zero_20261020_01`，不计测试通过。

## 复现

两轮静态对照仅改变临时配置的图像偏移；保留图像处理和相同的严格视觉平面修正诊断门槛。静态模式不解锁、不执行规划轨迹。

```bash
# 每轮使用新名称；先正常偏移，再做不飞行的敏感性试验。
bash astra/run_117.bash static cut_zero_NEW \
  --world-preset baylands \
  --scan-dir astra/runtime/maps/baylands_gc_receiver_20261018 \
  --seconds 45 --vio-max-planar-correction-m 0.000001 \
  --isolate-estimator-cpus

bash astra/run_117.bash static cut_negative_NEW \
  --world-preset baylands \
  --scan-dir astra/runtime/maps/baylands_gc_receiver_20261018 \
  --seconds 45 --vio-max-planar-correction-m 0.000001 \
  --img-time-offset-s -0.012 --isolate-estimator-cpus

source astra/env_117.bash
python3 astra/tools/audit_livo_cut_timing.py \
  astra/runtime/<正常轮> astra/runtime/<负偏移轮> \
  --output astra/runtime/cut_timing_comparison.json
```

历史及新静态对照汇总见 [结构化证据](livo_cut_timing_117.json)。原始 CSV、运行源码快照、参数恢复与运行状态在对应 `astra/runtime/<运行名>/`。

## 尚未解决的独立问题

正常 0 偏移、严格 VIO 修正门槛的一轮长路线成功，不能证明高度漂移已修复。同样严格门槛的 `final_vio_reject_20261019_01` 曾在 `405.152 s` 因冻结高度差超过 0.20 m 中止，当时 Odom 测量/接收年龄只有 44/3.71 ms，属于另一类故障。不能选择性忽略这次失败。

对该失败轮的完整核心日志进一步核查：3960 次 VIO 中，3953 次修正被拒绝，其余 7 次均在初始化阶段、没有接受任何视觉 patch。已记录的 IMU 处理后→VIO 更新后位置、yaw、速度、加速度偏置和重力分量没有可观察变化（数值容差 1e-9）。代码在拒绝时恢复完整 `StatesGroup`。因此，**大幅 VIO 状态修正不是此次高度漂移的必要条件**，不能继续把“视觉大修正”当作已确定的根因。

成功的严格门槛重复轮 5548 次 VIO 中，5539 次拒绝，仅一次有非零可观察更新，Z 约 0.000000412 m。日志未记录完整 roll/pitch 和协方差；统计没有把被拒绝的提议计入实际变化，也没有将修正增量相加冒充真值误差。两轮初始化和运动过程不同，不能据此独立证明某个时间或地图假设。

下一步应保留真实测量时间，重点比较图像参与/不参与时的 LIO 切片与传播时刻，再分解平面匹配、姿态、重力和加速度偏置贡献；相机几何和视觉地图的间接影响仍需保留为待验证项。此报告诊断阶段完整融合长路线重复尚未通过。后续正常 0 偏移、0.04 m VIO 门槛的同配置三轮约 71 m＋300 s 保持均通过，见[正常融合重复验收](NORMAL_LONG_ACCEPTANCE_117.md)；仅说明本轮未复现缺口或高度保护失败，不证明历史高度根因已修。项目仍处于**仿真收尾验收**。
