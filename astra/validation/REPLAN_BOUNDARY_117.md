# RViz 转弯重规划失败

2026-10-16，隔离 PX4 1.17 / Baylands 全图，位置 External Vision、0.20 m/s 规划速度与原有保护阈值。

## 用户失败轮

`outdoor_20261016_153602` 起飞后、尚未到达第一个航点时，以 `bridge fault: preview not tracking` 结束。进程没有崩溃，任务保护中止后降落上锁；该路线可靠性未通过。

| 事件 | 证据 |
| --- | --- |
| 第一个目标 | 地面冻结原点偏移 `(8.482017, 0.793342)` m |
| 第二个目标 | `(-6.771350, 19.217336)` m，尚未执行 |
| 最后一条接受轨迹 | id 23，测量时钟起点 173.792 s |
| 重规划失败 | 最终轨迹在 t≈0.40–0.45 s 被占据检查拒绝；多种种子连续失败 |
| 预览撤销 | 规划器耗尽三次重试，发布 trajectory_valid=false 并进入 WAIT_TARGET |
| 执行桥中止 | 仿真 175.280 s，墙钟 588339723756055 ns |
| 中止时 odom | 测量年龄 80 ms，接收年龄 26.68 ms，不是 250 ms 超时 |
| 实际模型位置 | 约 `(1.8801, 1.8496, 1.4767)` m |
| 恢复 | 冻结 PX4 保持位置；直线官方 RTL 走廊未认证，使用已检查的当前位置下降空间安全降落 |

`planner.log` 在墙钟 `[1792136356.662...]` 起反复记录 `Grid fallback rejected at t=0.400 XYZ=1.901 1.827 1.377`、`Rejecting colliding final trajectory` 和 `First 3 control points in obstacles`。

用当轮冻结原点、下降与通行区并集、原 0.4 m 跟踪余量重新构建安全掩码：上述拒绝点不在允许区；相邻的旧轨迹状态 `(1.8878,1.8015)` 仍在允许区。旧 id 23 通过原连续曲线边界检查，在转弯处最大 x 约 1.897 m，而对应掩码边缘 x≈1.9003 m。新起步段越界很小，但不能据此放松安全边界。

同时，稀疏保存的原始局部地图在 170.116–177.608 s 内，该拒绝点附近最近占据体素中心约 1.245 m，位置约 `(3.1,1.5,1.3)`；重新构建的共享边界已足以解释此次拒绝，不能把日志中的“障碍”直接理解为无人机撞上真实树木，也不能将此归因于 odom 接收超时。

## 修复

重规划失败后，不立即认定旧轨迹失效。只有仍有有效里程计、当前跟踪误差合格、剩余时间足够，并且**当前地图对旧轨迹全部剩余段的复查通过**，才保留原 id、原起始时间和原曲线，间隔一个原重规划周期重试。工作预算 5 ms、最多 10000 个检查间隔，任何检查不确定均不保留。

最多三次失败；没有延长旧曲线有效时间，也不重复重置失败计数。地图、边界、心跳、跟踪误差、碰撞检测和执行桥原门控继续生效；新障碍触发的碰撞检查可以立即要求重规划，不等待上述普通重试时刻。

preview 现在保存详细失效原因，监督器桥采样和异常信息记录该原因，避免以后只留下 `preview not tracking`。离线规划回放同步使用当轮实际通行区并集、Z 带和虚拟顶高，避免拿不同安全掩码解释原运行。

## 回归与复飞

278 项回归通过（3 个既有 Python 弃用警告）。新增用用户轨迹 id 23 前六个控制点验证：安全弯道可保留；旧曲线新增障碍、接近终点、时间无效、检查预算耗尽均拒绝；检查覆盖末端且不修改旧曲线。`bspline_opt`、`ego_planner`、`astra_px4_offboard` 编译通过。

本机回归日志：`astra/runtime/replan_corner_regression_20261016.log`；构建日志：`astra/runtime/replan_corner_build_20261016.log`。

离线输入回放 `replan_corner_baseline_20261016` 不是逐帧确定性复现：规划轨迹与真实闭环不同，部分曲线被独立边界检查拒绝，后续因回放位置与计划轨迹偏离而触发跟踪门控。因此不把该回放当作原失败的精确 A/B 或修复成功证据。

最终双航点复飞及完整审计已通过，详见文末结果；仍不等于重复或跨地图认证。

## 第二种触发：采样定时器落后

第一轮候选闭环 `outdoor_replan_corner_20261016_01` 到达第一个用户目标，开始飞向第二点，随后仍以相同桥状态中止并安全降落。该轮没有触发保留旧曲线分支，不能当作该分支的飞行认证。

这次规划器仍连续接受新曲线，预览也没有切换到 HOLD；桥在仿真 244.988 s 报错时，最后预览原因仍为 `tracking`。执行 trace 的墙钟记录：

| --- | --- |
| 最后一次预览 tick 开始 | 589242428273695 |
| 桥收到该次 preview_mode | 589242429541000 左右 |
| 二代 GC | 589242437625676–589242527646468，90.02 ms |
| 执行桥因模式消息超过 200 ms 中止 | 589242641434301 |
| 下一次预览 tick | 589242645368000 左右 |

两次预览 tick 间隔约 217.1 ms。GC 墙钟 90.0 ms、线程 CPU 50.2 ms，只解释其中一部分，不能把全部空档归给 GC 或 FAST-LIVO2 算法。中止时 odom 测量年龄 160 ms、接收年龄 44.2 ms。后续规划器的 0.60 m 跟踪保护发生在桥已停止轨迹执行之后，不能倒置为此次桥中止的首因。

### 同进程采样顺序修正

组合运行中，preview 与 bridge 原本就在同一线程：现在取消 preview 的独立输出定时器，由监督器每次发送周期先调用完整 preview 检查／采样，再直接传递同一份姿态、速度和模式给 bridge，随后运行 bridge 原检查。桥在组合模式不再订阅三个回环 preview 话题，避免迟到的旧回调覆盖刚生成的样本。ROS 预览话题继续提供给显示和诊断；独立运行节点默认仍使用 ROS 订阅与原定时器。

这不是延长 200 ms 或 250 ms 门槛。测量时间、odom 接收、地图／规划心跳、轨迹有效性、边界、速度、跟踪误差与重置门控均继续检查。若 planner 或 odom 真正失效，当前采样同样返回 HOLD/NO_VALID_HOLD，不能刷新成健康轨迹。新增串行采样与桥检查耗时记录。

280 项完整回归通过，新增覆盖定时器落后时有效输入的串行刷新、规划心跳过期、odom 过期、轨迹撤销以及组合模式不接受迟到的 preview DDS 回调。日志 `astra/runtime/replan_corner_regression_20261016_02.log`。

### 组合节点共用控制时钟

第二轮候选 `outdoor_replan_corner_20261016_02` 在交接后被 `stale measurement timestamp` 拦下，经官方 RTL 返回并降落上锁，没有执行有效目标位移，不计成功。

直接采样改变了原先 DDS 延迟关系，暴露了组合节点各自 `/clock` 回调排队不一致：中止时 preview 和监督器的时钟为 136.096 s，bridge 仍为 136.084 s；它把新生成的 136.096 s 预览当成未来 12 ms 的样本拒绝。这是串行改造必须补齐的时间基准问题，不能通过允许未来时间戳解决。

现在组合采样、bridge 的时间检查及 setpoint 时间戳共用监督器的同一个 ROS Clock 实例；各节点独立订阅的其他输入仍按原测量时刻和接收时刻检查。独立运行默认保留节点自身时钟。回归覆盖共享时钟下的串行交接，并验证超前共同时间 1 ns 的样本仍会被拒绝。
