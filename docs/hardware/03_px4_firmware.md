# PX4 固件、源码与烧录

[返回实物索引](README.md)

## 当前策略

实物第一阶段以与硬件型号匹配的官方 PX4 1.17 固件为基线；Astra 的定位、规划和轨迹桥运行在伴随计算机上。当前尚未提供经过实物验收的定制固件。

仿真并非完全没有 PX4 修改：[SITL 构建脚本](../../astra/build_px4_117.bash)会应用仓库保存的 POSIX HRT 重调度、Gazebo 磁力计和本地位置 DDS 输出上限 50→100 Hz 三项补丁。前两项针对 POSIX/Gazebo，不能直接当作真实飞控补丁；DDS 配置涉及遥测带宽和时间配对，需要在实物端单独评估。完整 PX4 源码存于独立目录，补丁文件存于本仓库。不要用该 SITL 脚本代替实物 target 构建。

“烧录源码”应拆成三个动作：

```text
获取官方 PX4 1.17 源码
  -> 为具体硬件 target 编译固件
  -> 通过 USB/DFU/厂商工具烧录固件
  -> 在 QGroundControl/PX4 shell 中配置参数
```

不能把 SITL 固件直接烧进实物飞控，也不能在没有确认 target 的情况下运行通用刷写命令。

## 烧录前记录

- 飞控型号和官方 target；
- 当前固件版本和可回滚固件；
- 参数导出文件；
- QGroundControl 或 DFU 连接方式；
- 电池、传感器和遥控器校准状态。

## 烧录后检查

1. 读取固件版本和 target；
2. 恢复或逐项配置参数，不直接覆盖未知参数；
3. 校准加速度计、陀螺仪、磁力计、遥控器和电源；
4. 配置 uXRCE-DDS 连接端口；
5. 桨叶拆除后检查 ROS 2 状态话题和 failsafe；
6. 保留参数导出和 ULog。

External Vision、Offboard 和串口参数必须以实际飞控端口和 PX4 1.17 文档为准。需要改 PX4 源码时，先写明缺口、补丁、target、回滚方式和新增测试。
