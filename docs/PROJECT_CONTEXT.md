## 当前实际链路

- PX4 控制的 x500 挂载等效 LiDAR、RGB/depth 相机和 IMU，传感器点时间与外参已针对仿真处理；不宣称完整模拟真实 Livox 扫描物理过程。
- FAST-LIVO2 是实际 LIO/VIO 算法，Gazebo 真值没有改名为 odom。输出为测量时刻状态；发布与接收时间另外记录。
- 局部地图检查 odom 跳变、新鲜度和体素规模，产生膨胀障碍与 readiness；规划器和执行保护使用共同通行掩码。旧地图从下降区域生成，新试验可独立指定巡航带与降落区。
- EGO 输出 B-spline；预览做全曲线/时间/速度/加速度检查，执行桥转换至 PX4 NED；监督器管理起降和唯一 setpoint 控制权。
- **External Vision 已实现并实测融合 XY/Z**，通过参数显式启用，默认关闭；不融合视觉 yaw 或速度。设置参数本身不是融合证据，验收看 ULog 标志与 aid-source 记录。
- RViz2 三维显示支持最多 8 个航点、空中追加、暂停/继续、末点降落或有时限等待；不是无限自主巡航界面。

## 关键已做决策

1. 优先完整低速 SITL 闭环，不继续把两套独立估计器的每个噪声差都当作 PX4 故障；随后以隔离 EV 实验减少位姿参考差异。
2. 不靠盲调 `min_eigen_value` 或放宽新鲜度/安全阈值认证定位。早期单次横移命令未产生有效真实运动，不能用于精度判断；必须记录实际轨迹。
3. 512 张灰度图像上限解决了短重复路线主要内存增长，20 分钟短路线 RSS 出现平台；宽范围长期内存尚无平台证明。
4. 仿真 snapshot 点时间、待处理 VIO 无需等下一扫描、可靠同步输入与调度优化已落地。算法墙钟耗时包含被调度暂停的时间，不能全部算为 CPU 算法成本。
5. 地面采集/验证并冻结高度与 EV 转换；飞行时不重估原点消除偏差。控制标定不使用 Gazebo 真值。
6. 规划器和执行器共同认可下降安全边界，避免规划出执行保护必然拒绝的路线；安全掩码和传感器障碍图职责不同。
7. 路线几何检查、规划曲线检查、任务完成、实际运动精度、同配置重复和跨地图通用性分别判定，不互相代替。
8. 每轮隔离 rootfs/参数，测试后清理并校验基线；保留失败证据。先修有日志证据的问题，不因猜测改大量参数。

## 未解决问题与下一步顺序

1. **推广与长时消息时效**：100 Hz 输出已经实际审计；事件模式东侧两轮完整往返通过。西侧一轮已通过，下一步扩展跨区、独立地图和长时运行，检查 GC／调度造成的延迟尾部；保护仍可能因输入迟到中止，不称偶发调度已全部解决。
2. **树旁长绕行**：检查拓扑/额外侵蚀及路径质量，与期限一起解释；不只是调大 timeout。尚未证明不存在更短安全路线。
3. **区域相关高度漂移**：树旁曾累积约 17 cm；新测试约 10 cm后回到经过区域减小。东/西未持续单向累积，仍不能消除区域问题。分解 VIO/LIO、平面/视觉特征和 IMU/地图影响。
4. **航点精度与重复性**：新远端往返已通过，但东侧 PX4 XY p95 仍约 11 cm；早期八航点与树旁路线的失败尚未由本轮覆盖。继续相同配置重复与复杂路线回归，保留所有结果。
5. **推广验证**：独立室外地图、自然树木细枝、长时运行/内存；风、动态障碍和坡地另列。当前固定高度和平面支持地面不验证地形跟随。
6. **实物准备**：真实传感器时钟、外参、机体/旋翼净空、延迟预算、RK3588性能、PX4接口和失效恢复需重新验收。
7. **恢复覆盖范围**：旧 RTL 配置曾因 `failsafe flags stale` 拒绝。新连通配置已覆盖一轮不可原地下降位置的地图失联恢复，使用检查过的通道撤到可降落点；仍需多区域重复、PX4 reset/遥测失效等故障覆盖。保持旧证据与拒绝条件，不把单轮通过视为全图恢复认证。
